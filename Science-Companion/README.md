# Science 中文与外部打开 1.2.2

适用于 Windows 的 Edge 浏览器版 Claude Science。保持扩展 ID 不变，不修改 Claude Science 或 CSSwitch 程序。

## 更新与首次安装

1. 完整解压压缩包，运行 `Install-or-Update.cmd`。必须同时更新扩展和本地组件，不能只替换 extension 文件夹。
2. 打开 `edge://extensions`，找到“Science 中文与外部打开”，点击重新加载，确认版本为 1.2.2。首次安装则开启开发人员模式，点击“加载解压缩的扩展”，选择安装脚本显示的 **extension 子文件夹**，其中必须直接包含 manifest.json。
3. 刷新 Science 网页。在扩展面板点击“检查本地打开组件”，确认组件版本也是 1.2.2。

首次安装默认位置：`%LOCALAPPDATA%\CSSwitch\Science-Companion`。更新时自动沿用已有的、身份匹配的组件目录，也支持 `Install.ps1 -InstallRoot <目录>`。不需要 G 盘。请保留浏览器实际加载的目录。

## 原文件与外部应用

在 Science 文件的操作菜单中使用：

- **用默认应用打开**：将原文件路径交给 Windows 文件关联。
- **选择其他应用打开**：调用 Windows 应用选择窗口，不修改默认文件关联。
- **在文件资源管理器中显示**：定位并选中实际磁盘文件，包括 Science 内部存储的成果和历史版本，不调用下载、不创建副本。

支持的文件格式不再局限于 Markdown。PDF、Word、Excel、图片、文本、FASTA、压缩包及其他格式均可交给 Windows 处理；需要本机已有对应应用。程序、脚本和系统操作类文件另有明确的打开确认。

本机文件从当前菜单的 Science 文件引用取得；成果文件使用元数据接口的 file_path，这是 Science 存储服务解析后的实际磁盘路径。旧版本通过版本列表按 version_id 精确匹配其 file_path。ref_host_path 为空也能定位内部文件。不会扫描硬盘、按文件名猜路径或自行按 ID 拼接存储目录（Science 可能对相同内容去重）。路径不存在、无法访问或无法确认版本时明确提示，不改用其他版本。

**外部编辑会直接修改实际磁盘文件。** 对 Science 内部存储文件直接保存改动，可能导致版本校验和文件内容不一致；查看或定位不修改内容，编辑建议仍在 Science 中保存为新版本。插件不会主动修改文件内容、数据库或文件属性，也不创建打开副本。

## 服务器文件与没有原路径的附件

只要附件或历史版本已经保存在 Science 本机存储中，就可以直接定位。尚未保存到本机的 SSH 服务器文件，以及元数据确实没有可用路径的对象，才需要其他处理。Windows 文件资源管理器无法直接定位未挂载的服务器文件。

- “在文件资源管理器中显示”会解释原因，始终不下载副本。
- 另外两个打开入口会先询问是否保存缓存副本。拒绝则不保存。接受后原样保存二进制内容，再交给外部应用。
- 相同文件名、相同内容会复用缓存，避免每次增加新文件。已被外部编辑的缓存会保留，最多另存一份原内容备用；两份都被修改时提示处理，不覆盖修改。
- 缓存副本位于安装目录的 `Cache`，不会同步回 Science 或服务器。不同版本保留不同缓存，可自行清理。旧版的 Exports 不会被升级删除。
- 缓存打开单文件上限 64 MiB；直接打开本机原文件没有插件设置的大小上限。更大远程文件可使用 Science 原有下载功能。
- 本版支持带盘符的 Windows 本机路径。未挂载的 SSH 路径、Mac 路径和 UNC 网络路径不会直接打开。

## 1.2.1 路径修复

1.2.0 错误地只检查 ref_host_path，忽略了 file_path，导致内部成果被提示“Science 未提供路径”。1.2.1 补用实际存储路径，支持精确定位历史版本，并补充成果列表菜单、长文档及 React 刷新后的选中项识别。没有修改 Science 的程序或存储格式。

## 1.2.2 菜单与沙箱提示修复

- 对话里的成果卡片、正文文件链接与图片采用不同的文件标识，现在分别识别其实际选中项和版本。若无法确认目标，不再建议下载可能不对应当前版本的副本。
- PDF 等独立成果预览没有普通“下载”菜单项，之前因此漏加外部打开功能。现在三个入口不依赖“下载”项，Markdown 的入口保留。
- 新增或调整 12 条 Windows 沙箱设置相关中文，包括设置横幅、批准按钮和不同状态说明。

“完成 Windows 沙箱设置”表示 Science 正在等待额外的 Windows 管理员批准。关闭横幅只会暂时隐藏提示，重新加载页面或状态变化后可能再次出现。需要启用时，点击“请求 Windows 批准”（Ask Windows now），并自行处理 Windows 的管理员窗口；完成后应显示“已开启”（On）。插件不会申请或自动接受管理员权限，也不会隐藏未完成状态。此提示涉及 Git、命令提示符脚本及 PowerShell 切换目录；提示本身不代表 Python 单元也无法运行。

词表合计 2,074 条。补充词表共有 247 条，涵盖连接器账号状态、SSH 身份验证、网络及超时、PDF/表格预览、保存/上传/下载失败、Windows 沙箱、计算环境、权限及存储设置等。

截图中的“Directory connectors unavailable”和 claude.ai 会话过期说明已补齐。翻译只是显示层变化，不会修复登录过期或其他服务错误。

文档正文、代码、输入框内容、研究数据单元格与技术路径保留；错误详情中的动态参数保持原样。扩展面板可随时关闭中文，查看原始诊断。未收录的后台新错误、第三方页面和 Science 升级后的新文本仍可能为英文，不承诺覆盖所有运行时字符串。

## 适用范围及验证

只在标题含 Claude Science、地址为 localhost / 127.0.0.1、端口为 8990 / 8765 / 8000 的网页生效，不影响 Science 独立桌面窗口。

扩展仅在明确点击后读取当前文件菜单的引用。读取成果元数据时使用页面现有会话，鉴权信息不发送给本地打开组件。外部打开不通过命令行拼接执行。

已通过原生消息与路径校验、缓存复用、二进制保真、六种格式的三个入口、历史版本防混淆，以及 20 类界面和 247 条补充词条的隔离 Edge 测试。实际扩展的 MAIN 页面脚本和元数据请求也已验证，测试中的系统打开调用使用记录替代。

1.2.2 另外直接提取 Science 0.1.60 的菜单、菜单状态钩子、对话成果卡片和图片包装组件，使用同版 React 渲染后加载真实扩展验证。正文链接和成果预览使用源码对应的菜单调用及属性结构搭建测试。共验证 31 次当前/历史文件打开请求、缺失版本拒绝，下载请求为 0。此验证不等于已经在当前用户页面或外部应用中验收。

本次另只读核对了当前电脑真实 Science 中的 Markdown、Word、PDF 和历史版本：4 组样本的元数据及抽查版本路径均存在，且 ref_host_path 均为空。没有读取文档正文或启动外部应用。尚未在你的另一台电脑、实际 Science 文件菜单与外部应用组合中验收。Science 升级改变菜单结构时插件可能需要更新，无法确认时会给出提示。

卸载：从 Edge 移除扩展，并在组件目录运行 `Unregister.ps1`。该操作仅注销本组件，保留原文件和缓存。
