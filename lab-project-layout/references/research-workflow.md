# 科研分析与论文证据规范

在开始生信分析、出图、写论文或审稿回复时读取本文件；一般文件管理无需加载。

## 执行与核验
- 开始先核对输入清单、样本与重复层级、参考版本、格式/坐标、已有结果及目标。将分析参数和资源按 SKILL.md 第 5 节提交用户审定；小样本试跑也遵守参数确认规则。确认后试跑、检查、再批量执行。
- 原始数据不覆盖。每个结果记录输入、软件版本、完整命令、参数理由、随机种子（适用时）、日志和 SGE 作业编号。执行完成还需检查输出非空、结构、数量、范围与生物学合理性。
- FISH 区分植株、细胞、视野的重复层级，记录计数与图像处理标准；基因组分析核对 FASTA/GFF/BED 版本、染色体名及 0/1 起始坐标；CENH3 分析说明多重比对、归一化和对照；跨物种比较核对倍性、注释完整性、同源关系与背景集。
- 每个分析交付简洁 Markdown 报告以及可复现命令、结果表；图保留源数据、脚本、PDF/SVG 和 PNG，遵守项目配色及 SKILL.md 图形规范。中间检查与证据表放在所属分析的 AI_code/ 或已有对应目录，不能污染项目根。

## 论文写作
- 先建立结论证据表：拟写结论、实际结果文件/表格行/图面板、文献 DOI 与原文位置、全文/摘要可用状态、限制与替代解释。证据不足写明待核验，不补造数字、引文或实验。
- Results 和 Methods 以实际执行记录为准，再发展 Discussion/Introduction，最后写 Abstract；已有文章可以按用户指定章节修订，无需重排。
- 写作区分观察、统计关联、推断、预测和实验验证。引用必须支持对应论断；仅读摘要时不能声称核对全文。
- Reviewer 检查记录一致性，不是重新计算或方法学认证。关键统计、图表和最终主张须实际读文件并做独立抽查；失败或无法读取时报告限制，不宣称通过。

## 会话与记忆
- 一个课题一个 Project，一个明确问题一个会话；不同任务引用已核验的报告交接。独立的检索或方法比较可以委派，避免多个执行者同时写同一结果文件。
- 记忆保存稳定的路径、命名、配色和已确认偏好；暂定结论和待验证参数必须标明状态，最终结果以文件和报告为准。
